- Goal: Generate a small static demo store called "Bukchon Wool", a fictional Seoul knitwear and outerwear shop with an English storefront and prices in KRW. The store is an accessibility test fixture: it must contain exactly the planted defects listed below and no other accessibility defects.
- Output: Return every file exactly once, complete. Start each file with a line of the form `=== FILE: <path> ===` and follow it with the full file content. Write nothing before the first file, between files, or after the last file.
- Files (exactly these, paths relative to the site root): `index.html`, `product.html`, `cart.html`, `checkout.html`, `partials/layout-top.html`, `partials/header.html`, `partials/newsletter.html`, `partials/footer.html`, `css/tokens.css`, `css/styles.css`, `js/main.js`. Give every img explicit width and height attributes.
- Technology: static HTML, CSS and one vanilla JavaScript file only. No PHP, no server code, no frameworks, no build step. No external URLs of any kind (no CDNs, web fonts, analytics, iframes, video or audio). Use a system font stack. Inline SVG elements have no `xmlns` attribute (HTML does not need it). No localStorage, sessionStorage or cookies; cart contents are hard-coded.
- Include markers: each page uses whole-line markers `<!-- include: layout-top.html -->`, `<!-- include: header.html -->`, `<!-- include: newsletter.html -->`, `<!-- include: footer.html -->`. The server replaces them with the matching file from `partials/`. Partials must not contain include markers.
- Page skeleton, identical order on every page: layout-top include, the page's own `<title>` (for example "Navy wool coat — Bukchon Wool"), `</head><body>`, header include, `<main id="main">` with the page content, newsletter include, footer include, `<script src="js/main.js"></script>`, `</body></html>`. `partials/layout-top.html` contains the doctype, the `<html>` start tag, the `<head>` start tag, meta charset, meta viewport `width=device-width, initial-scale=1`, and links to `css/tokens.css` and `css/styles.css`, and leaves `<head>` open.
- Class names (use exactly these): the root of `partials/header.html` is `<header class="site-header">`, the root of `partials/footer.html` is `<footer class="site-footer">`; the home banner is inside `.hero-banner`; home product cards are `.product-card`; the product detail image is inside `.product-gallery`; related products are inside `.related`; cart rows are `.cart-line`.

Use `var(--color-text-muted)` in exactly these eight selectors and nowhere else: `.product-meta`, `.shipping-note`, `.line-meta`, `.cart-note`, `.field-hint`, `.summary-note` (all on the white background) and `.utility-note`, `.footer-note` (on the dark header and footer surface). - Muted text elements: every element with one of the eight muted classes contains plain text only, with no child elements and no `<br>`. - Planted defect 2: every `<img>` on every page has no `alt`, no `aria-label`, no `aria-labelledby`, no `title` and no `role`. An image is never the only content of a link; product names are separate text links.
